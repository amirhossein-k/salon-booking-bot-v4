# اصلاح مدیریت کارکنان سالن

این بسته، «سازنده نسخه اصلاح‌شده» است، نه ZIP کامل مخزن. اسکریپت، نسخه بررسی‌شده مخزن عمومی را دانلود می‌کند، اصلاحات را روی کپی موقت اعمال می‌کند و ZIP کامل پروژه را می‌سازد. فایل‌های موجود و دیتابیس شما را تغییر نمی‌دهد. دانلود روی کامپیوتر شما به اینترنت نیاز دارد.

مخزن:
https://github.com/amirhossein-k/salon-booking-bot-v4

نسخه مبنا:
2b72f48cab57dc3a1aaa3725c72c022ca4417434

## ساخت ZIP کامل

Python نسخه 3.11 یا جدیدتر لازم است. همه فایل‌های این بسته را در یک پوشه استخراج کنید، ترمینال را همان‌جا باز کنید و اجرا کنید:

```bash
python build_fixed_project.py
```

در ویندوز، در صورت نیاز:

```powershell
py -3 build_fixed_project.py
```

خروجی، `salon-booking-bot-v4-fixed.zip` است. این ZIP شامل کل مخزن اصلی و فایل‌های اصلاح‌شده است. از ZIP موجود به‌عنوان خروجی استفاده نمی‌کند و چیزی را بازنویسی نمی‌کند.

اگر دانلود از داخل اسکریپت ممکن نبود، ZIP همین نسخه را با مرورگر بگیرید:

https://github.com/amirhossein-k/salon-booking-bot-v4/archive/2b72f48cab57dc3a1aaa3725c72c022ca4417434.zip

سپس:

```bash
python build_fixed_project.py --source-zip original.zip
```

فایل‌های اصلی پیش از اصلاح با Git blob SHA بررسی می‌شوند؛ ZIP نسخه دیگری پذیرفته نمی‌شود.

## قابلیت‌ها و محدوده

این اصلاحات برای استقرار آنلاین `app.py` با Vercel و MongoDB نوشته شده‌اند. داشبورد محلی SQLite (`dashboard.py`) این مدیریت جدید را ندارد و تنظیمات MongoDB را نمی‌خواند. ربات polling محلی هم نباید هم‌زمان با webhook آنلاین اجرا شود.

از داشبورد اصلی یا موبایل، روی «مدیریت کارکنان» کلیک کنید. مسیر جدید `/staff` است و از همان ورود مدیر داشبورد استفاده می‌کند.

برای کارکنان فعلی، نام، شناسه عددی تلگرام، خدمات، ساعات کاری هفتگی و فعال/غیرفعال بودن پنل ربات قابل تغییر است. نوبت‌ها قابل مشاهده و تعیین وضعیت هستند؛ زمان را می‌توان مسدود یا باز کرد. ساخت یا حذف کارکنان جدید اضافه نشده است؛ شناسه‌های اصلی کارکنان و خدمات در `config.json` تعریف می‌شوند.

تنظیمات مدیر در MongoDB، مجموعه `staff_settings` و سند `staff` ذخیره می‌شود و بر مقادیر کارکنان در `config.json` اولویت دارد. حذف سند تنظیمات، مقادیر config را دوباره فعال می‌کند؛ برای قطع دسترسی از داشبورد استفاده کنید، نه حذف دستی سند.

## اتصال آرایشگر به ربات

آرایشگر در گفتگوی خصوصی ربات `/start` و سپس `/id` را ارسال می‌کند. مدیر این شناسه را برای همان آرایشگر در داشبورد ثبت می‌کند. یک شناسه برای دو آرایشگر مجاز نیست. شناسه مدیر هم نباید به کارکنان اختصاص داده شود: مدیر ذاتاً دسترسی همه را دارد.

کاربر عادی فقط رزرو و نوبت‌های خودش را می‌بیند. کارمند مجاز، با انتخاب پنل، مستقیماً وارد پنل خودش می‌شود. مجوز در سمت سرور و عملیات نوبت و زمان بررسی می‌شود، نه فقط در ظاهر دکمه‌ها. شناسه از اطلاعات فرستنده آپدیت معتبر تلگرام می‌آید، نه از ورودی دستی کاربر.

تغییر شناسه یا غیرفعال کردن پنل، در درخواست بعدی ربات اثر می‌کند. دکمه‌های قدیمی هم مجوز قبلی را زنده نگه نمی‌دارند. پیش از ارسال اعلان‌های صف‌شده نوبت، دسترسی گیرنده دوباره بررسی می‌شود. پیام‌های از قبل ارسال‌شده قابل پس گرفتن نیستند؛ پاسخ‌های رابط ربات که پیش از تغییر مجوز در صف بوده‌اند نیز ممکن است برسند، اما عملیات بعدی نیازمند مجوز فعلی است.

غیرفعال بودن «پنل ربات» فقط دسترسی مدیریتی همان کارمند را قطع می‌کند و به معنی حذف او از رزرو مشتریان نیست. برای تعطیلی از ساعات کاری یا مسدود کردن زمان استفاده کنید.

## استقرار

قبل از استقرار از MongoDB نسخه پشتیبان بگیرید و ابتدا روی محیط آزمایشی بررسی کنید. ZIP خروجی را استخراج و روی پروژه Vercel فعلی مستقر کنید. هیچ کلید یا رمز واقعی در این بسته قرار داده نشده است؛ متغیرهای محیطی موجود را حفظ کنید.

`DASHBOARD_ADMIN_ID` باید شناسه‌ای داخل `admin_ids` در `config.json` باشد. `DASHBOARD_PASSWORD`، `CSRF_SECRET`، `MONGODB_URI`، `MONGODB_DB`، `BOT_TOKEN` و `TELEGRAM_WEBHOOK_SECRET` طبق راهنمای اصلی پروژه لازم هستند. مسیرهای مدیریتی جدید ورود مدیر، CSRF و اعتبارسنجی ورودی دارند.

MongoDB باید replica set داشته باشد، مثل Atlas. اسکریپت اولیه پروژه `scripts/init_db.py` باید قبلاً اجرا شده باشد تا اسناد guard موجود باشند. مجموعه تنظیمات جدید خودکار در اولین ذخیره ایجاد می‌شود؛ نوبت‌ها و مشتریان حذف نمی‌شوند.

ساعات کاری به وقت تهران است. تغییر ساعات کاری نوبت‌های قبلی را لغو نمی‌کند. برای وضعیت لغو توسط سالن، ابتدا با مشتری هماهنگ کنید.

## تست و محدودیت بررسی

در محیط ساخت، ۳۶ تست مستقل اعتبارسنجی، تنظیمات، مرزهای مجوز مسیرها و اعمال وصله روی نمونه شبیه‌سازی‌شده اجرا شده‌اند. نحو کد JavaScript هم بررسی شده است. اتصال واقعی MongoDB، Telegram و استقرار Vercel در این محیط آزموده نشده‌اند؛ دانلود و اجرای سازنده روی ZIP واقعی مخزن هم به دلیل نبود اینترنت در محیط ساخت اجرا نشده است. اسکریپت سازنده، هنگام اجرا روی کامپیوتر شما صحت نسخه اصلی و نحو همه فایل‌های Python خروجی را بررسی می‌کند؛ این بررسی جای تست یکپارچه را نمی‌گیرد.

پس از ساخت ZIP کامل، در پوشه پروژه:

```bash
python -m unittest discover -s tests -p test_staff_management.py -v
python -m unittest discover -s tests -p test_routes.py -v
```

تست‌های اصلی پروژه را هم مطابق راهنمای اصلی اجرا کنید. سپس با سه حساب آزمایش کنید: مدیر، آرایشگر مجاز و مشتری عادی. آرایشگر اول نباید نوبت یا پنل آرایشگر دوم را مدیریت کند. پس از تغییر شناسه، حساب قبلی نباید با دکمه‌های قدیمی عملیات انجام دهد.
