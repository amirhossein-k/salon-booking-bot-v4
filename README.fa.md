# ربات نوبت‌دهی سالن زیبایی، نسخهٔ ۴

کد قابل اجرای ربات تلگرام با رابط فارسی، Python 3.11 به بالا و SQLite.
این بسته روی تلگرام مستقر نشده است. اتصال واقعی نیاز به توکن جدید، اینترنت سرور و اجرای دائمی دارد.
توکن افشاشدهٔ شما عمداً در هیچ‌یک از فایل‌ها قرار نگرفته و استفاده نمی‌شود.

**داشبورد مدیریتی اضافه شده است:** راهنمای `DASHBOARD.fa.md` را بخوان.
**داشبورد ویژهٔ موبایل:** راهنمای `MOBILE.fa.md` و فایل `dashboard-mobile.html` اضافه شده‌اند.
نسخهٔ واقعی موبایل با همان ورود مدیر در مسیر `/mobile` سرویس داشبورد در دسترس است.
فایل مستقل `dashboard.html` پیش‌نمایش نمونه است؛ اجرای `dashboard.py` آن را به دیتابیس واقعی وصل می‌کند.
درآمد از مبلغ دریافتی ثبت‌شده برای نوبت‌های انجام‌شده محاسبه می‌شود، نه قیمت فرضی.
داشبورد، تقویم شمسی و یادآوری‌های نسخهٔ قبل را حفظ می‌کند.

## امکانات

- انتخاب خدمت، آرایشگر، روز و ساعت شروع از بازه‌های واقعاً آزاد.
- سه خدمت نمونه: کوتاهی مو، ناخن و مژه؛ برای هرکدام دو آرایشگر مستقل.
- مدت خدمت متفاوت، فاصلهٔ رزرو ۱۵ دقیقه، حداقل یک ساعت فاصله تا زمان نوبت، افق رزرو ۲۱ روز.
- دریافت نام و تلفن و تأیید نهایی مشتری.
- جلوگیری از هم‌پوشانی در لحظهٔ ثبت با تراکنش قفل‌شدهٔ SQLite، حتی برای چند درخواست هم‌زمان.
- اعلان به مشتری، آرایشگر مربوط و مدیر سالن با صف پایدار و تلاش مجدد.
- پنل آرایشگر برای دیدن نوبت‌های روز، ساعت‌های آزاد، بستن کل روز یا بازهٔ ساعت و بازکردن آن.
- وضعیت‌های «رزرو قطعی»، «لغو توسط سالن»، «لغو توسط مشتری»، «عدم حضور» و «انجام شد».
- ثبت توضیح، زمان تغییر و شناسهٔ تغییر‌دهنده؛ نوبت لغوشده از تاریخچه پاک نمی‌شود.
- آرایشگر فقط اطلاعات و برنامهٔ خودش را می‌بیند؛ مدیر همهٔ کارکنان را مدیریت می‌کند.
- استفاده فقط در گفتگوی خصوصی، برای جلوگیری از انتشار نام و شماره در گروه.
- /start برای ورود، /cancel برای قطع مرحلهٔ جاری و /id برای دیدن شناسهٔ عددی تلگرام.
- تقویم شمسی با نام ماه و روز فارسی در انتخاب روز، برنامهٔ کارکنان و جزئیات نوبت.
- یادآوری خودکار به مشتری، به‌صورت پیش‌فرض ۲۴ ساعت و ۲ ساعت قبل از شروع.

## ارتقا از نسخهٔ قبلی

ابتدا از دیتابیس نسخهٔ پشتیبان بگیر و ربات را متوقف کن.
فایل‌های کد را با نسخهٔ جدید جایگزین کن؛ فایل جدید `jalali.py` را هم حتماً کپی کن.
فایل شخصی `.env`، تنظیمات واقعی `config.json` و دیتابیس یا Docker volume قبلی را نگه دار.
`config.example.json` را روی تنظیمات واقعی خودت کپی نکن.
اگر Docker استفاده می‌کنی، فایل `Dockerfile` و `compose.yaml` جدید را هم جایگزین و اجرا کن:

```bash
docker compose up -d --build
```

اگر سرویس systemd استفاده می‌کنی، بعد از جایگزینی فایل‌ها:

```bash
sudo systemctl restart salon-bot
```

ساختار دیتابیس قبلی خودکار و بدون حذف نوبت‌ها ارتقا می‌یابد.
نوبت‌های قطعی قبلی هم برای یادآوری‌های آینده بررسی می‌شوند.
تاریخ پیام‌های قبلاً ارسال‌شده تغییر نمی‌کند، اما نمایش‌های جدید شمسی خواهند بود.
تاریخ‌ها و ساعت‌های داخلی و callbackها همان قالب قبلی را دارند تا رزروهای قبلی خراب نشوند.

## تنظیم یادآوری خودکار

این دو کلید اختیاری را به `config.json` واقعی اضافه کن:

```json
"reminder_minutes": [1440, 120],
"reminder_grace_minutes": 30
```

عددها دقیقهٔ قبل از شروع هستند: ۱۴۴۰ یعنی ۲۴ ساعت و ۱۲۰ یعنی ۲ ساعت.
برای فقط یک یادآوری یک‌ساعته از `[60]` و برای غیرفعال‌کردن از `[]` استفاده کن.
اگر این کلیدها در تنظیمات نسخهٔ قبلی وجود نداشته باشند، همین پیش‌فرض‌ها اعمال می‌شوند.
بعد از تغییر تنظیمات، ربات را راه‌اندازی مجدد کن.

یادآوری فقط به مشتری ارسال می‌شود؛ اعلان رزرو و تغییر وضعیت همچنان برای مشتری، آرایشگر و مدیر است.
ربات باید روشن و به اینترنت متصل باشد؛ زمان ارسال معمولاً با تأخیر کوتاه در چرخهٔ polling بررسی می‌شود.
اگر ربات خاموش یا شبکه قطع باشد، یادآوری تا ۳۰ دقیقه پس از زمان مقرر قابل ارسال است.
پس از این مهلت یا زمان شروع نوبت، یادآوری قدیمی ارسال نمی‌شود.
اگر رزرو بعد از موعد یک یادآوری ثبت شده باشد، آن یادآوری از دست‌رفته ارسال نمی‌شود؛
مثلاً رزرو سه ساعت قبل از شروع، یادآوری ۲۴ ساعته ندارد اما یادآوری ۲ ساعته خواهد داشت.
قطع اجرا یا حجم زیاد صف می‌تواند تأخیر ایجاد کند؛ زمان ارسال تضمین لحظه‌ای ندارد.

هر یادآوری با کلید پایدار «شناسهٔ نوبت + فاصلهٔ یادآوری» ثبت می‌شود، بنابراین راه‌اندازی مجدد آن را دوباره زمان‌بندی نمی‌کند.
یادآوری ارسال‌نشدهٔ نوبت لغوشده متوقف می‌شود و وضعیت نوبت درست پیش از ارسال دوباره بررسی می‌شود.
پیامی که قبلاً تحویل شده پس از لغو قابل پس‌گرفتن نیست؛ اعلان لغو به مشتری ارسال می‌شود.
قطع بسیار کوتاه درست پس از ارسال و قبل از ثبت تحویل ممکن است باعث پیام تکراری شود.
برای آزمایش، یک نوبت در آینده بساز و موقتاً فاصلهٔ یادآوری را طوری تنظیم کن که موعد آن چند دقیقه بعد باشد.
اعلان آزمایشی واقعی فقط پس از اجرا و اتصال سرور به تلگرام ارسال خواهد شد.

تقویم بدون کتابخانهٔ اضافی کار می‌کند و برای تاریخ‌های میلادی ۱۹۰۰ تا ۲۱۰۰ محدود شده است.
برچسب روزها نام ماه شمسی دارد و متن کامل نوبت سال/ماه/روز شمسی را نشان می‌دهد.

## ۱. توکن را عوض کن

در ربات رسمی @BotFather، دستور /revoke را بفرست و ربات موردنظر را انتخاب کن تا توکن قبلی باطل شود.
توکن تازه را از BotFather دریافت کن و فقط در فایل خصوصی `.env` روی سرور قرار بده.
توکن را در چت، سورس، اسکرین‌شات یا گیت قرار نده.

## ۲. تنظیمات واقعی سالن را وارد کن

از پوشهٔ پروژه:

```bash
cp config.example.json config.json
cp .env.example .env
```

فایل `.env` را در ویرایشگر سرور باز کن و مقدار `BOT_TOKEN` را با توکن جدید جایگزین کن.
فایل `config.json` شامل داده‌های نمونه است، نه نام یا برنامهٔ تأییدشدهٔ سالن شما.
شناسهٔ مدیر برای تست برابر `622650522` تنظیم شده است.

برای هر آرایشگر:

1. `name` را با نام واقعی عوض کن.
2. کارمند ربات را در تلگرام Start کند و /id بفرستد.
3. عدد دریافتی را در `telegram_id` قرار بده؛ عدد بدون کوتیشن، نه نام کاربری و نه شمارهٔ موبایل.
4. `services` را مطابق خدمات واقعی او تنظیم کن.
5. `weekly_hours` را تنظیم کن؛ برای تعطیلی یک روز، کلید را حذف کن یا مقدارش را `[]` بگذار.

مثال یک آرایشگر با زمان ناهار:

```json
{
  "id": "nail1",
  "name": "نام واقعی ناخن‌کار اول",
  "telegram_id": 123456789,
  "services": ["nails"],
  "weekly_hours": {
    "0": [["09:00", "13:00"], ["14:00", "18:00"]],
    "1": [["10:00", "17:00"]],
    "5": [["09:00", "18:00"]]
  }
}
```

عدد مثال بالا شناسهٔ واقعی کارمند نیست.
روزهای هفته: ۰ دوشنبه، ۱ سه‌شنبه، ۲ چهارشنبه، ۳ پنجشنبه، ۴ جمعه، ۵ شنبه، ۶ یکشنبه.
زمان‌ها به وقت `Asia/Tehran` هستند. تاریخ‌های رابط در این نسخه شمسی‌اند.
بازهٔ کاری شبانه را به دو روز تقسیم کن؛ انتهای بازه باید بعد از شروع همان روز باشد.
مدت هر خدمت در `duration_minutes` تنظیم می‌شود. برای کاشت و ترمیم ناخن با مدت متفاوت، دو خدمت جدا تعریف کن.
می‌توان خدمات بیشتری اضافه کرد و یک آرایشگر را به چند خدمت اختصاص داد؛ تداخل بین همهٔ خدمات همان آرایشگر بررسی می‌شود.

`telegram_id: null` یعنی اعلان و ورود پنل برای آن کارمند فعال نیست؛ مدیر همچنان برنامهٔ او را مدیریت می‌کند.
تلگرام به ربات اجازهٔ پیام‌دادن به کاربری که هنوز آن را Start نکرده نمی‌دهد.
اگر کارمند ربات را مسدود کند، اعلان در صف می‌ماند و دوباره تلاش می‌شود؛ ارسال فوری تضمین‌شده نیست.
مدیر از «وضعیت اعلان‌ها» می‌تواند تعداد اعلان‌های ارسال‌نشده و کارکنان فاقد شناسه را ببیند.

شناسه‌های `id` باید ثابت، انگلیسی و کوتاه باشند.
بعد از رزرو واقعی، شناسهٔ خدمت یا آرایشگر را حذف یا عوض نکن؛ نوبت‌های قبلی به آن شناسه وابسته‌اند.
تغییر مدت خدمت روی پایان نوبت‌های قبلی اثر ندارد.
تغییر تنظیمات نیاز به راه‌اندازی مجدد ربات دارد.
تغییر ساعت کاری، نوبت قطعی قبلی را خودکار لغو نمی‌کند؛ ابتدا با مشتری هماهنگ کن.

## ۳. اجرای محلی یا روی سرور با پایتون

Python 3.11+ و دادهٔ منطقهٔ زمانی سیستم لازم است؛ کتابخانهٔ پایتونی جانبی نیاز نیست.
در لینوکس، بستهٔ `tzdata` باید نصب باشد.
اگر در ویندوز خطای `ZoneInfoNotFoundError` دیدی:

```powershell
py -m pip install tzdata
$env:BOT_TOKEN = Read-Host "New bot token"
py bot.py
```

در لینوکس، پس از تنظیم `.env`:

```bash
mkdir -p data
chmod 700 data
chmod 600 .env config.json
set -a
. ./.env
set +a
python3 bot.py
```

فقط یک پردازش polling برای یک توکن اجرا کن.
سرور به اینترنت و دسترسی HTTPS به `api.telegram.org` نیاز دارد؛ webhook و دامنه لازم نیست.
اگر از قبل webhook برای این ربات فعال بوده، این کد عمداً آن را خودکار پاک نمی‌کند:
نسخهٔ قبلی را متوقف و webhook آن را از برنامهٔ قبلی یا با روش Telegram Bot API غیرفعال کن.
هنگام انتخاب روش polling مطمئن شو ربات قدیمی دیگر فعال نیست.

## ۴. اجرای دائمی با Docker Compose

روی سروری که Docker و افزونهٔ Compose دارد، `.env` و `config.json` را طبق بالا آماده کن.
نسخهٔ محلی را هم‌زمان با Docker روشن نگذار.
فایل تنظیمات در کانتینر باید برای کاربر غیرریشه خواندنی باشد؛ توکن در `.env` باقی می‌ماند:

```bash
chmod 600 .env
chmod 644 config.json
docker compose up -d --build
docker compose logs -f --tail=50
```

دیتابیس در named volume به نام `salon_data` ذخیره می‌شود.
`docker compose down` آن را نگه می‌دارد؛ **گزینهٔ `-v` داده‌ها را حذف می‌کند، استفاده نکن**.
بعد از تغییر تنظیمات:

```bash
docker compose restart bot
```

توکن در متغیر محیطی است و افراد دارای دسترسی مدیریتی به Docker می‌توانند آن را بخوانند؛ دسترسی سرور را محدود کن.

## روش جایگزین: systemd در لینوکس

این روش را به‌جای Docker استفاده کن، نه هم‌زمان با آن.
فایل نمونهٔ `salon-bot.service` آماده است.
کاربر سیستم `salon` بساز، پروژه را در `/opt/salon-bot` قرار بده و مالکیت آن را به همان کاربر بده.
فایل `.env` باید متعلق به آن کاربر و با مجوز `600` باشد.
پوشهٔ `data` را قبل از شروع سرویس ایجاد و برای کاربر `salon` قابل نوشتن کن.
سپس فایل سرویس را به `/etc/systemd/system/salon-bot.service` کپی کن:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now salon-bot
sudo journalctl -u salon-bot -f
```

فایل سرویس مسیر `/usr/bin/python3` را فرض می‌کند؛ قبل از اجرا نسخهٔ آن را بررسی کن.

## تست عملی

1. مدیر با حساب شناسهٔ `622650522` ربات را Start کند.
2. یک کارمند واقعی Start کند و شناسهٔ او را در `config.json` وارد کن، سپس ربات را دوباره اجرا کن.
3. با حساب مشتری، خدمت، آرایشگر و زمان آزاد را انتخاب و نام و تلفن را وارد کن.
4. پس از تأیید، پیام جزئیات باید برای مشتری، کارمند مربوط و مدیر ارسال شود.
5. همان آرایشگر و همان بازهٔ زمانی دیگر قابل رزرو نیست؛ آرایشگر دوم همچنان مستقل است.
6. از پنل آرایشگر یک بازهٔ خالی را ببند؛ آن ساعت نباید برای مشتری نمایش داده شود.
7. یک نوبت را با توضیح لغو کن؛ تاریخچه حفظ و آن زمان دوباره آزاد می‌شود.
8. برای روز تعطیل کامل، در مرحلهٔ مسدودکردن بنویس: `تمام‌روز مرخصی`.

برای شبیه‌سازی سریع، می‌توان موقتاً شناسهٔ مدیر را به `telegram_id` یکی از آرایشگران هم داد.
این فقط تست نقش‌ها و دریافت اعلان است؛ در کار واقعی، هر کارمند شناسهٔ جداگانه داشته باشد.
به دلیل تجمیع گیرندگان، یک حساب هم‌زمان مدیر و آرایشگر فقط یک اعلان برای هر رویداد می‌گیرد.

## لغو اضطراری و عدم حضور

پنل کارکنان ← انتخاب آرایشگر ← نوبت‌ها و ساعت‌های آزاد ← روز ← جزئیات نوبت.
وضعیت مناسب را انتخاب و دلیل را وارد کن، سپس تأیید نهایی بده.
«لغو توسط سالن» با «لغو توسط مشتری» متفاوت ذخیره می‌شود.
برای لغو اضطراری، اول با شمارهٔ مشتری تماس بگیر؛ ربات تماس خودکار انجام نمی‌دهد.
«عدم حضور» و «انجام شد» فقط بعد از زمان شروع قابل ثبت‌اند.
در این نسخه وضعیت نهایی دوباره تغییر نمی‌کند؛ تصحیح اشتباه نیاز به رسیدگی مدیر در دیتابیس دارد.
بازکردن یک بازهٔ مسدود، نوبت لغوشده را دوباره زنده نمی‌کند.
مسدودکردن بازه‌ای که نوبت قطعی دارد رد می‌شود تا نوبت مشتری بدون هماهنگی حذف نشود.

## تست‌های خودکار

از پوشهٔ پروژه:

```bash
python3 -m unittest discover -s tests -v
```

تست‌ها دیتابیس موقت می‌سازند و به تلگرام وصل نمی‌شوند.
موارد پوشش‌داده‌شده: رزرو هم‌زمان، هم‌پوشانی، استقلال کارکنان، ساعات کاری، دسترسی،
لغو و تاریخچه، صف اعلان، تلاش مجدد، حفظ مرحله پس از راه‌اندازی مجدد و جریان رزرو فارسی،
تقویم و اسفند کبیسه، زمان‌بندی یادآوری، توقف پس از لغو، عدم تکرار زمان‌بندی،
ارتقای دیتابیس قبلی و اعتبارسنجی ساختاری تمام روزهای ۱۹۰۰ تا ۲۱۰۰.
این تست‌ها جای تست واقعی روی تلگرام و سرور را نمی‌گیرند.

## پشتیبان‌گیری و حریم خصوصی

نام، شماره و تاریخچه در دیتابیس SQLite روی سرور ذخیره می‌شود و در پیام خصوصی تلگرام ارسال می‌شود.
دیتابیس این نسخه رمزگذاری داخلی ندارد؛ پوشه، سرور و نسخهٔ پشتیبان باید خصوصی باشند.
اطلاعات مشتریان فقط برای آرایشگر همان نوبت و مدیر قابل مشاهده است.
متن اعلان‌ها و مراحل نیمه‌تمام هم ممکن است حاوی شماره باشند.
پیش از راه‌اندازی عمومی، رضایت مشتری، سیاست نگهداری و حذف داده و الزامات محلی را مشخص کن.
پنل حذف دادهٔ مشتری و سیاست پاک‌سازی خودکار در این نسخه پیاده‌سازی نشده است.

برای اجرای پایتونی، از ابزار backup استفاده کن تا داده‌های WAL هم درست کپی شوند:

```bash
python3 backup.py
```

نسخهٔ پشتیبان در `backups/` با مجوز خصوصی ساخته می‌شود؛ آن را در مخزن عمومی قرار نده.
برای Docker، چون دیتابیس روی named volume است، این دستور نسخهٔ سالم را روی میزبان می‌سازد:

```bash
mkdir -p backups
chmod 700 backups
umask 077
docker compose exec -T bot python -c 'import sqlite3; s=sqlite3.connect("/app/data/salon.sqlite3"); d=sqlite3.connect("/tmp/salon-backup.sqlite3"); s.backup(d); d.close(); s.close()'
docker compose cp bot:/tmp/salon-backup.sqlite3 backups/salon-backup.sqlite3
docker compose exec -T bot python -c 'import os; os.remove("/tmp/salon-backup.sqlite3")'
```

برای بازیابی، ربات را متوقف کن و با فرد فنی نسخهٔ پشتیبان را جایگزین کن؛ فایل‌های قدیمی WAL/SHM باید با احتیاط مدیریت شوند.

## مرزهای این نسخه

- رابط داخل ربات تلگرام است، نه سایت یا Mini App.
- پرداخت، بیعانه، پیامک و تغییر زمان مستقیم پیاده‌سازی نشده‌اند.
- برای تغییر زمان، نوبت قبلی را با دلیل لغو و نوبت جدید ثبت کن.
- تغییر ساعات هفتگی و مشخصات کارکنان از فایل تنظیمات است؛ تعطیلی موردی از پنل ربات.
- یادآوری‌ها از طریق تلگرام هستند، نه پیامک یا تماس تلفنی.
- دیتابیس SQLite مناسب یک سالن و یک نمونهٔ اجرایی است؛ برای چند سرور هم‌زمان باید معماری تغییر کند.
- صف اعلان تحویل «حداقل یک‌بار» دارد؛ قطع اجرا درست بعد از ارسال ممکن است پیام تکراری ایجاد کند.
- بازگشت کاربر از مسدودکردن ربات باعث می‌شود تلاش‌های بعدی اعلان‌های صف را ارسال کند.
- آخرین نوبت‌های مشتری در منو نمایش داده می‌شوند؛ تاریخچهٔ کامل در دیتابیس باقی می‌ماند.
- نرخ تلاش‌های ناموفق و صف اعلان‌ها باید در استفادهٔ واقعی پایش شود.
- تست زندهٔ Telegram، انتشار روی سرور و ارزیابی امنیتی پیش از استفادهٔ عمومی هنوز لازم‌اند.
